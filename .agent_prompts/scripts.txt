Read new_autoresearcher.md in the project root first — that is the full system specification.

You are building SCRIPTS, TEMPLATES, and GIT INTEGRATION inside autoresearch_v2/scripts/ and autoresearch_v2/templates/.

YOUR FILES (create these and ONLY these):
  autoresearch_v2/scripts/__init__.py
  autoresearch_v2/scripts/git_integration.py  — Git operations: branch, commit, tag (via subprocess)
  autoresearch_v2/scripts/setup.sh            — Initialize git repo + .gitignore + directory structure
  autoresearch_v2/scripts/sync_logs.sh        — rsync backup with lockfile
  autoresearch_v2/scripts/retriever.py        — Research retrieval CLI (GitHub PR search + arxiv)
  autoresearch_v2/templates/__init__.py
  autoresearch_v2/templates/types.py          — Template-specific types
  autoresearch_v2/templates/loader.py         — YAML template loader with placeholder substitution
  autoresearch_v2/templates/sweep.py          — Sweep generator: template * param values -> N YAML configs
  autoresearch_v2/templates/architecture.yaml
  autoresearch_v2/templates/hyperparameter.yaml
  autoresearch_v2/templates/ttt.yaml
  autoresearch_v2/templates/evaluation.yaml

DO NOT create or modify files outside autoresearch_v2/scripts/ and autoresearch_v2/templates/.

DESIGN REQUIREMENTS:
1. git_integration.py: GitManager class wrapping git subprocess calls.
   - __init__(repo_path: Path) — validates git repo or inits one
   - create_experiment_branch(exp_id: str) -> str (branch name)
   - commit_experiment_results(exp_id: str, status: str, metrics: dict[str, float]) -> str (commit hash)
   - tag_promotion(exp_id: str, metrics: dict[str, float]) -> str (tag name)
   - get_experiment_lineage(exp_id: str) -> list[str]
   Handle edge cases: not a git repo (auto-init), branch exists (skip), dirty tree (stash+pop), detached HEAD (checkout main first). Use _run_git() helper.

2. Templates: YAML with {{ placeholder }} syntax. TemplateEngine class with str.replace in a loop — NO Jinja2. Validate all placeholders filled (raise TemplateError if {{ }} remain).

3. sweep.py: CLI and importable.
   CLI: python -m autoresearch_v2.templates.sweep --template architecture --param NUM_LAYERS --values 6,7,8,9 --parent exp_000_baseline --prefix arch_layers
   Generates: autoresearch_v2/queue/arch_layers_001.yaml ... arch_layers_004.yaml
   Importable: generate_sweep(template, param, values, parent, prefix) -> list[Path]

4. Template YAML format:
   id, name, parent, hypothesis, category, priority, env_overrides (dict), stages (list), reject_if_worse_by (float)

5. retriever.py: CLI tool. Subcommands:
   - search "query" — grep local records/ directory for matching PRs
   - arxiv "query" — search arxiv API (export.arxiv.org/api/query)
   - pr NUMBER — fetch PR details from GitHub API
   Cache in autoresearch_v2/db/retriever_cache.json. Handle network errors gracefully.

6. setup.sh: .gitignore (db/*.db-wal, db/*.db-shm, __pycache__, *.pyc, experiments/*/*.pt, .ruff_cache), git init, initial commit.

7. sync_logs.sh: BACKUP_DIR as env var or arg. flock lockfile. rsync -av --exclude='*.pt'. Log timestamp.


CODE STANDARDS (mandatory for all files you write):

1. TYPING: Every function signature must have full type annotations (params + return). Use typing module: Optional, List, Dict, Union, Protocol, TypeVar, etc. Use dataclasses or NamedTuple for structured data — no raw dicts for internal state. Use Enum for finite state sets (experiment status, priority, stage).

2. LINTING: Your code must pass: python -m py_compile <file> at minimum. Write code that would pass ruff/mypy strict. No bare except:, no mutable default args, no unused imports.

3. PATTERNS:
   - @property for computed attributes (never expose raw internal state)
   - Builder pattern for complex object construction (experiment configs)
   - Abstract base classes (abc.ABC + @abstractmethod) for interfaces that have multiple implementations
   - Context managers (__enter__/__exit__) for resource lifecycle (DB connections, GPU locks, file handles)
   - dataclasses with frozen=True for immutable value objects
   - Protocols (typing.Protocol) for structural subtyping where ABC is overkill

4. STYLE: Minimal comments — code should be self-documenting via types and names. Docstrings on public classes and non-obvious public methods only (Google style). No inline comments that restate what the code does. Private methods prefixed with underscore. Constants in UPPER_SNAKE_CASE at module top.

5. ERROR HANDLING: Define custom exception hierarchy (AutoResearchError base). Never catch Exception broadly — catch specific types. Use logging module, not print(). Log level: DEBUG for step-by-step, INFO for stage transitions, WARNING for retries, ERROR for failures.

6. IMPORTS: stdlib first, then third-party, then local. One import per line. No wildcard imports.

7. STRUCTURE: Each module should have a clear single responsibility. If a file exceeds 300 lines, it probably needs splitting. __all__ exports at top of each module.

IMPLEMENTATION ORDER:
1. templates/types.py (TemplateConfig dataclass, TemplateError exception)
2. templates/loader.py (TemplateEngine class)
3. Template YAML files (all four)
4. templates/sweep.py (depends on loader)
5. scripts/git_integration.py (standalone)
6. scripts/retriever.py (standalone)
7. Shell scripts (setup.sh, sync_logs.sh)

After each .py file, run: python -m py_compile on it.

Dependencies: PyYAML for YAML parsing (pip install pyyaml --break-system-packages if needed). urllib for arxiv API. Everything else stdlib.
