You are building the CORE SYSTEM for AutoResearch v2 inside autoresearch_v2/core/ and autoresearch_v2/autoresearch.py.

YOUR FILES (create these and ONLY these):
  autoresearch_v2/core/__init__.py
  autoresearch_v2/core/types.py          — Enums, dataclasses, type aliases shared across modules
  autoresearch_v2/core/exceptions.py     — Custom exception hierarchy

  autoresearch_v2/core/config.py         — YAML config loader + validation (using dataclass schema)

DO NOT create or modify files outside autoresearch_v2/core/ and autoresearch_v2/autoresearch.py.

SHARED TYPES (in types.py — other agents will import from here):
  - ExperimentStatus(Enum): DEFINED, QUEUED, SCREENING, GATING, PROMOTING, DONE, REJECTED, FAILED
  - ExperimentPriority(Enum): CRITICAL, HIGH, NORMAL, LOW
  - Stage(Enum): SCREEN, GATE, PROMOTE
  - ExperimentCategory(Enum): ARCHITECTURE, HYPERPARAMETER, EVALUATION, TTT
  - @dataclass(frozen=True) ExperimentConfig: id, name, parent_id, hypothesis, category, priority, env_overrides, stages, expected_direction, reject_if_worse_by, script_path
  - @dataclass ExperimentResult: screen metrics, gate metrics, promote metrics (all Optional)
  - @dataclass GPUSlot: slot_id, gpu_indices (tuple[int,...]), assigned_experiment (Optional[str])
  - @dataclass MetricEvent: timestamp, step, train_loss, lr, ms_step, gpu_mem_gb, tokens_seen

DESIGN REQUIREMENTS:
1. Registry: Use a context manager for DB connections. WAL mode. Parameterized queries only (no f-strings in SQL). Provide a RegistryReader (read-only Protocol) that the dashboard agent can import without pulling in write logic.
2. GPUSlotManager: Thread-safe (threading.Lock). Methods return Optional[GPUSlot] — never raise on "no slot available", just return None. Support reconfiguration: 4x2 for screening, 2x4 for mixed, 1x8 for promote.
3. Runner: Build the torchrun command via a RunCommandBuilder (builder pattern). Subprocess management via context manager. Metrics parsing via a generator that yields MetricEvent from stdout lines.
4. Monitor: Implement as a Protocol so the gate agent can provide its own health checks. Default impl: NaNDetector, OOMDetector, StallDetector — each is a small class implementing the HealthCheck Protocol.
5. Scheduler: The main loop is a single method _tick() called every 5s. Separate the "what to do" logic from the "do it" logic — _tick returns a list of Action objects (LaunchScreen, LaunchGate, KillExperiment, etc.) which are then executed. This makes the scheduler testable without GPUs.
6. CLI: Use argparse with subparsers. Each subcommand is a function. The 'daemon' subcommand runs the scheduler loop with signal handling (SIGTERM/SIGINT → graceful shutdown).


CODE STANDARDS (mandatory for all files you write):

1. TYPING: Every function signature must have full type annotations (params + return). Use typing module: Optional, List, Dict, Union, Protocol, TypeVar, etc. Use dataclasses or NamedTuple for structured data — no raw dicts for internal state. Use Enum for finite state sets (experiment status, priority, stage).

2. LINTING: Your code must pass: python -m py_compile <file> at minimum. Write code that would pass ruff/mypy strict. No bare except:, no mutable default args, no unused imports.

3. PATTERNS:
   - @property for computed attributes (never expose raw internal state)
   - Builder pattern for complex object construction (experiment configs)
   - Abstract base classes (abc.ABC + @abstractmethod) for interfaces that have multiple implementations
   - Context managers (__enter__/__exit__) for resource lifecycle (DB connections, GPU locks, file handles)
   - dataclasses with frozen=True for immutable value objects
   - Protocols (typing.Protocol) for structural subtyping where ABC is overkill

4. STYLE: Minimal comments — code should be self-documenting via types and names. Docstrings on public classes and non-obvious public methods only (Google style). No inline comments that restate what the code does. Private methods prefixed with underscore. Constants in UPPER_SNAKE_CASE at module top.

5. ERROR HANDLING: Define custom exception hierarchy (AutoResearchError base). Never catch Exception broadly — catch specific types. Use logging module, not print(). Log level: DEBUG for step-by-step, INFO for stage transitions, WARNING for retries, ERROR for failures.

6. IMPORTS: stdlib first, then third-party, then local. One import per line. No wildcard imports.

7. STRUCTURE: Each module should have a clear single responsibility. If a file exceeds 300 lines, it probably needs splitting. __all__ exports at top of each module.

After each file, run: python -m py_compile autoresearch_v2/core/<file>.py to verify syntax.

Use only Python stdlib (sqlite3, subprocess, threading, argparse, logging, pathlib, dataclasses, enum, typing, json, signal, time, abc). No pip installs.
